RESEARCH NOTE · FLYRANK ML INTERNSHIP CAPSTONE

Which pages lose search visibility first?

A validated, honestly-evaluated model for ranking content refresh priority from one month of search signals — tested against a transparent rule baseline on 176,738 pages of real production search data.

Can a page's own March search signals predict whether it will lose visibility in April, well enough to help an editor decide what to review first? We built and validated a Decision Tree on 176,738 pages from FlyRank's production search warehouse, using a client-grouped split to avoid inflated, leaky estimates. The model reached an Average Precision of 0.611 against a base rate of 0.578 and a transparent rule baseline of 0.587 — a real, modest improvement, not a breakthrough. A naive (non-grouped) split scored a misleadingly higher 0.674, demonstrating exactly how much client-level leakage can inflate a result if the validation design isn't honest. The output is offered as a ranked, human-reviewed content refresh shortlist — decision-support, not certainty.

01 Introduction

Content teams sit on portfolios of thousands of pages and cannot manually review all of them every month. Someone has to decide which pages get attention first — and today, that decision is usually a guess based on whichever page an editor happened to notice.

The decision this project supports is narrow and concrete: given one month of a page's search performance, which pages should a content editor look at first, before the next month's report arrives? The person acting on the answer is a content editor with a limited review budget. The cost of getting it wrong is real but bounded either way: a wasted review, or a real decline left unreviewed for another month.

A single hand-written rule can already do part of this job. The question this paper actually answers is whether a small, readable model can do it a little better than that rule — and whether the way we measure "better" can be trusted.

02 Data

This project uses the fact_content_daily_performance table from the FlyRank internship warehouse release, hosted on Hugging Face. Two mid-panel months were used: March 2026 as the feature window and April 2026 as the outcome window. The final month in the panel (June 2026) was treated as a sealed test month and was never used to develop any label or feature logic.

Page-day rows were grouped and summed to one row per client-page pair per month before any modeling — the unit of analysis is a page, not a page-day.

Excluded, and why

  • trend_direction, trend_pct — rule-derived columns. Using either as a label or feature risks the model re-learning a threshold rule instead of finding real signal.
  • AI-referral columns — largely missing outside GA4-available rows, not needed for this question.
  • All client and content identifiers are pseudonymized hashes, used only to group and split data — never as model inputs, and never displayed.

Public-safety note: no client names, raw search queries, or private identifiers appear anywhere in this page, the underlying notebooks, or the repository.

03 Methodology

Label

target_decline = 1 if a page's total April impressions were lower than its total March impressions, else 0. This is an observed cross-month outcome, not a category defined by a rule — a deliberate correction after an earlier draft of this project considered using the rule-derived trend_direction field.

Features

Three signals, all knowable before the outcome window:

  • march_impressions — total March search impressions
  • march_clicks — total March clicks
  • march_position — traffic-weighted average March ranking position

Baseline

A transparent, hand-written rule: score = 2 × log(1 + impressions), with a plain reason code for pages with high visibility and a rankable position. No fitted weights — readable by design.

Model

A depth-3 Decision Tree Classifier. Depth was kept shallow deliberately: a tree a person can print and read teaches more than an opaque model a few points stronger.

Validation design

A GroupShuffleSplit by client (test size 0.22, seed 42) ensures no client's pages appear in both train and test. A naive random split — ignoring client grouping — was also run, specifically to make the cost of skipping this step visible rather than assumed.

Leakage checks

Two independent leakage tests were run over the course of this project, each by deliberately injecting a feature that determines the label by construction and confirming the score jumps sharply:

On the final feature set, no feature correlated with the target above 0.04 in magnitude — no disguised label proxy was found.

Reading this honestly: the model adds real but modest skill — roughly three points of Average Precision above the rule baseline, and roughly three points above chance. The naive split's higher number is not a better result; it is the size of the leakage the grouped split closes.

05 Limitations

OBSERVATIONAL

Nothing here proves that refreshing a page causes a change in performance — only that certain March signals are associated with an April decline.

MODEST SKILL

0.611 vs a 0.578 base rate is a real but small improvement. This is decision-support, not a high-confidence forecast.

COARSE RANKING

The shallow tree produces only a handful of distinct probability values — read "priority" as tiers, not a strict page-by-page order.

NARROW FEATURES

Three signals cannot capture content quality, competitor moves, or algorithm changes — a page can decline for reasons invisible to this model.

LIMITED POPULATION

Trained on 36 clients, tested on 11, from one 17-month snapshot — not validated on clients or periods outside this dataset.

GLOBAL WINDOW

One March/April window was used for every client, without checking each client's individual history depth.

06 Ranked recommendations

The validated model scores each held-out page with a decline probability, grouped into plain-language priority tiers — not a black-box number alone.

High-visibility, weak rank REVIEW FIRST

Pages that still carry meaningful visibility but show signs of slipping rank. The closest match in this project's own data to the FlyRank research paper's freshness-window finding (a 7.88:1 growth-to-decline ratio at 31–90 days) — offered as a directional rationale for prioritization, not a causal guarantee.

Low-visibility pages, any rank LOW PRIORITY

Limited traffic means limited value in a manual review right now, and any change in a small impression count is closer to noise than signal.

Human review is mandatory — never automated

  • Publishing content changes based on the model's ranking
  • Deindexing or deprioritizing a page without a human reading it
  • Using the score as a performance metric for a writer or editor
  • Treating decline probability as a certainty score rather than a rank

4,438 of 43,247 held-out pages (the bottom 10% by volume) are explicitly flagged as needing extra review before acting — their impression counts are small enough that normal noise could flip the label.

Monitoring & retrain triggers

  • Retrain if a future evaluation's Average Precision drifts back toward the base rate — the current skill margin is 0.034.
  • Retrain if the client or content mix shifts materially from the 36 clients seen in training.
  • Retrain on a routine cadence (e.g. quarterly) to account for algorithm and seasonality shifts this snapshot cannot see.

07 Reproducibility

Every number on this page was computed in a public notebook, with a fixed random seed (random_state=42) throughout, using scikit-learn's GroupShuffleSplit and DecisionTreeClassifier.
